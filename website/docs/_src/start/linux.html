Nostr Vault for Linux turns a Linux machine into your always-on vault: a Raspberry Pi, a mini PC, a home server or a desktop. It runs on the machine itself, with no Docker, and starts when the machine does. On a desktop it also has a window and a tray icon, like the Mac app. Your phones and computers reach it on your home network and over the mesh.

This is a beta. Linux is new in 3.2.3 and comes as a GitHub pre-release, v3.2.3-linux-beta.3. What works and what doesn't yet is at the end of this page.

What you need

  • A 64-bit machine: arm64 (a Raspberry Pi 4 or 5) or amd64 (x86-64). A 32-bit system is refused.
  • One of these systems, each with its own package in the release:
    • Debian 12 or newer, Ubuntu 22.04 or newer, or Raspberry Pi OS 12 (64-bit): the .deb.
    • Fedora: the .rpm (checked with SELinux enforcing).
    • Arch Linux and Arch Linux ARM: the .pkg.tar.zst.
    • Alpine 3.22 or newer: the .apk (OpenRC, no window or tray).
    • Any desktop with Flatpak (Steam Deck, Fedora Silverblue, Bazzite and others): the .flatpak. It has no mesh in this beta.
    • NixOS: the flake's NixOS module, below.
  • Your npub, the public key of the account that owns the vault. The machine never gets your secret key.
  • Room to store your notes and media. A USB SSD is much better than an SD card; see Raspberry Pi.

Install the .deb (Debian, Ubuntu, Raspberry Pi OS)

Open a terminal on the machine (or ssh into it) and download the file for your machine from the beta release: …_arm64.deb for a Raspberry Pi or other ARM board, …_amd64.deb for a normal PC. Then:

sudo apt install ./nostr-vault_3.2.3+6582_arm64.deb
sudo nostr-vault-setup --owner npub1…

On a machine with no screen, add --no-install-recommends to the first line so apt skips the window's libraries. nostr-vault-setup also takes --data /path for where the vault lives (a USB SSD is much better than an SD card) and --port (8080 to start). It starts the vault and prints the address to open, for example http://192.168.1.20:8080/.

Check the file first against SHA256SUMS in the release: sha256sum -c --ignore-missing SHA256SUMS.

Fedora, Arch and Alpine

Download the package for your system and machine from the beta release (x86_64 for a normal PC, aarch64 for ARM), then install it and set the owner:

# Fedora
sudo dnf install ./nostr-vault-3.2.3+6582-1.x86_64.rpm
# Arch Linux
sudo pacman -U ./nostr-vault-3.2.3+6582-1-x86_64.pkg.tar.zst
# Alpine (as root)
apk add --allow-untrusted ./nostr-vault-3.2.3_p6582-r0.x86_64.apk

sudo nostr-vault-setup --owner npub1…   # on Alpine, as root: nostr-vault-setup --owner npub1…

Each one is the same vault as the .deb, with the mesh, and runs the vault and the mesh as their own users, nvvault and nvmesh. On Fedora the package labels its programs for SELinux, so they run as an ordinary service. The .rpm and Arch package have the window and tray like the .deb; the Alpine apk has none, so open the vault from another device. On Alpine the services are OpenRC's: rc-service nostr-vault stop, and the logs are in /var/log/nostr-vault/.

The Alpine apk is signed with a throwaway key made for this build, so apk needs --allow-untrusted. Check the file against SHA256SUMS in the release first.

Flatpak, for desktops (no mesh)

Download nostr-vault-…-x86_64.flatpak (or aarch64) from the beta release, then:

flatpak install --user ./nostr-vault-3.2.3+6582-x86_64.flatpak

Open Nostr Vault from your apps. The Flatpak is different from the packages above:

  • No mesh. Device sync is off in the Flatpak for now. Your phones reach this vault on your home network only, not away from home.
  • The vault and the tray only, and it runs only while you're logged in. It starts at login (your desktop asks once) and keeps running when you close the window; quit it from the tray or with Ctrl+Q.
  • It is not on Flathub. Updates come from installing a newer bundle.

For a vault that runs on boot and syncs over the mesh, use the native package for your system instead.

NixOS (flake and module)

On NixOS, add the flake and turn on its module instead of installing a package. In your system flake:

inputs.nostr-vault.url = "github:btcforplebs/nostr-vault/v3.2.3-linux-beta.3";

# in your nixosSystem modules:
nostr-vault.nixosModules.default
{
  services.nostr-vault = {
    enable = true;
    owner = "npub1…";      # your npub, never an nsec
    openFirewall = true;   # 8080 on your network
  };
}

Then sudo nixos-rebuild switch. It is the same vault and mesh as the packages above, for x86_64-linux and aarch64-linux, with the vault and the mesh as their own users, nvvault and nvmesh, and its data in /var/lib/nostr-vault. Other options: port, dataDir, mesh.enable and environmentFile for secrets (a path outside the Nix store); the full list is in nix/README.md. It has no window or tray, so open the vault from another device. Logs: journalctl -fu nostr-vault -u nostr-vault-mesh. To update, point the input at a newer release and rebuild. Nostr Vault is not in nixpkgs yet.

On a desktop: the window

You can skip the terminal on a desktop. Install the package, then open Nostr Vault from your apps. The first page, Welcome to Nostr Vault, asks the same two questions: Your npub and Where your vault lives. Click Start my vault. Your computer asks for your password once, to set the vault up as a service, and the window opens the vault when it's ready.

The window is the web app, served by your own vault: Feed, Vault, My Devices and Settings. Closing it doesn't stop the vault. The tray icon shows the vault's status (for example Vault running · 2 devices on the mesh) and has Open Nostr Vault, New Note, Feed, Vault, My Devices, Settings and Copy box npub.

Open your vault and link it

  1. On a phone or computer on the same network, open the address nostr-vault-setup printed. Sign in with your Nostr account, the one whose npub you gave.
  2. In Settings, This Box → Status, storage, mesh, devices and updates shows the box's own page. Copy This box under My Devices.
  3. On your phone or Mac, add the box to My Devices by that address. The steps are on A Linux box in My Devices.

You're done when your phone shows the box in reach under Your Devices, and the box's page lists your phone as Approved.

Day to day

  • Logs: journalctl -fu nostr-vault -u nostr-vault-mesh
  • Stop or start: sudo systemctl stop nostr-vault (the mesh stops with it) and sudo systemctl start nostr-vault
  • Settings: sudo nostr-vault-setup --show; change them with sudo nostr-vault-setup --owner … --data … --port …
  • Update: install the newer package from its release the same way (apt install, dnf install, pacman -U, apk add). Your data, owner and port stay. Check for update and install on the box's page says the same for now.
  • Move the vault to another drive with Move vault to… on the box's page. Giving nostr-vault-setup --data a different folder starts an empty vault there instead.

What works, and what's still beta

Works now:

  • Your vault as a relay and media server on your network, started on boot, with the web app on http://<machine>:8080/.
  • The mesh, in the native packages (.deb, .rpm, Arch, Alpine) and on NixOS: your phones and Macs reach the box away from home once it's in My Devices. The mesh runs as its own user, makes its own mesh key and only lets in your own devices.
  • Native packages for Debian, Ubuntu, Raspberry Pi OS, Fedora, Arch and Alpine, a Flatpak for desktops, and a Nix flake with a NixOS module.
  • The desktop window and tray, on a machine with a desktop.
  • The box's page: status, storage and Move vault to…, the mesh, your devices, and Public on the web for a box with its own web address.

Not yet:

  • No in-app updates. Install the newer package to update.
  • The download is checked against a sha256 from the same release. That catches a broken download, not a forged one, because releases aren't signed yet.
  • The Flatpak has no mesh: device sync is off in it for now, and it runs only while you're logged in.
  • The Alpine apk is signed with a throwaway key, so it needs apk add --allow-untrusted.

Something wrong? Open an issue on GitHub with the output of journalctl -u nostr-vault -u nostr-vault-mesh --since today.
