The mesh address is one new entry form, fipsmesh://<npub>/, in lists you already use: the media server list (kind:10063) and, later, the relay list (kind:10002). In a relay list it goes in its own fipsmesh tag, not an r entry, so clients without mesh support never try to connect to it; Nostr Vault doesn't publish that tag yet. Linking a device never writes the media server list: Nostr Vault adds a fipsmesh entry only when you add a vault yourself under Media Servers → Your Vaults on the Mesh and save. No new event kinds. Requests are plain Blossom GET /<sha256>, with the same hash check.

A client that doesn't know the form skips it and carries on with the other servers in the list. A client that does can ask the device for the photo by its fingerprint, the same way it asks any media server, and throws the photo away if the fingerprint doesn't match.

Other NIPs worth knowing

  • Drafts (NIP-37). Drafts are kind:31234 with only d and k tags outside; the draft itself is NIP-44 encrypted to your own key. Older plaintext drafts are re-saved encrypted once. They go to your own vault, not to public relays.
  • File notes (NIP-94). Your vault keeps a kind:1063 note for each file in your media, on its own /files relay. Only you and the readers you name can read it.
  • Encrypted files in messages (NIP-17 kind:15). Test vectors are in docs/DM_FILE_VECTORS.json.

Build Nostr Vault

Everything is in one repository, btcforplebs/nostr-vault:

  • HavenApp/: the iPhone, iPad and Mac app (Swift). just ios-build or just macos-build.
  • NostrVault/: the Android app (Kotlin). just android-build.
  • haven-go/: the relay (Go), compiled into the apps as libhaven.
  • web-vault/: the web app. npm ci, then npm run dev or npm run build.
  • web-relay/: the browser vault.
  • fips-bridge/, fips-v2/ and fips-v2-android/: the mesh (FIPS) engine embedded in the apps, and its probes (Rust).
  • linux/: a Dockerfile to build the vault for a Linux box yourself (no published image yet).
  • linux/ also has install.sh, which sets up a vault on a Linux box. Updates are manual: run it again.
  • docs/: the NIP drafts, including NIP-F1, and the contracts between the apps and the vault.
