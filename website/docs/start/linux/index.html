    Get started on Linux

    Nostr Vault for Linux turns a Linux machine into your always-on vault: a Raspberry Pi, a mini PC, a home server or a desktop. It runs on the machine itself, with no Docker, and starts when the machine does. On a desktop it also has a window and a tray icon, like the Mac app. Your phones and computers reach it on your home network and over the mesh.

    This is a beta. Linux is new in 3.2.3 and comes as a GitHub pre-release, v3.2.3-linux-beta.1. What works and what doesn't yet is at the end of this page.

    What you need

    • A 64-bit machine: arm64 (a Raspberry Pi 4 or 5) or amd64 (x86-64). A 32-bit system is refused.
    • Debian 12 or newer, Ubuntu 22.04 or newer, or Raspberry Pi OS 12 (64-bit). These get the native package.
    • On Arch, Fedora and other systems without apt, the installer runs the vault in Docker instead. Native packages for those come later.
    • Your npub, the public key of the account that owns the vault. The machine never gets your secret key.
    • Room to store your notes and media. A USB SSD is much better than an SD card; see Raspberry Pi.

    Install with one command

    Open a terminal on the machine (or ssh into it) and paste this. It installs the beta from its release:

    curl -fsSL https://raw.githubusercontent.com/btcforplebs/nostr-vault/master/linux/install.sh | NV_NATIVE=1 NV_RELEASE=https://github.com/btcforplebs/nostr-vault/releases/download/v3.2.3-linux-beta.1 sh

    Keep the NV_RELEASE= part while Linux is in beta. Without it the installer looks at the newest full release, which doesn't carry the Linux package yet, and sets the vault up in Docker instead.

    The installer asks two questions:

    1. Where should your vault live? It suggests the drive with the most free space. If that is an SD card it warns you first and asks before it carries on.
    2. Your npub. Only that account can manage the vault. Nobody can claim it by visiting first.

    Then it downloads the package for your machine, checks it against the sha256 in the release, installs it, starts the vault and prints the address to open, for example http://192.168.1.20:8080/ and http://<machine name>.local:8080/.

    On a machine with a desktop, the installer adds the window and tray. On a machine with no screen it leaves them out.

    Or install the .deb yourself

    Download the file for your machine from the beta release: …_arm64.deb for a Raspberry Pi or other ARM board, …_amd64.deb for a normal PC. Then:

    sudo apt install ./nostr-vault_3.2.3+6534_arm64.deb
                sudo nostr-vault-setup --owner npub1…

    On a machine with no screen, add --no-install-recommends to the first line so apt skips the window's libraries. nostr-vault-setup also takes --data /path for where the vault lives and --port (8080 to start).

    On a desktop: the window

    You can skip the terminal on a desktop. Install the package, then open Nostr Vault from your apps. The first page, Welcome to Nostr Vault, asks the same two questions: Your npub and Where your vault lives. Click Start my vault. Your computer asks for your password once, to set the vault up as a service, and the window opens the vault when it's ready.

    The window is the web app, served by your own vault: Feed, Vault, My Devices and Settings. Closing it doesn't stop the vault. The tray icon shows the vault's status (for example Vault running · 2 devices on the mesh) and has Open Nostr Vault, New Note, Feed, Vault, My Devices, Settings and Copy box npub.

    Open your vault and link it

    1. On a phone or computer on the same network, open the address the installer printed. Sign in with your Nostr account, the one whose npub you gave.
    2. In Settings, This Box → Status, storage, mesh, devices and updates shows the box's own page. Copy This box under My Devices.
    3. On your phone or Mac, add the box to My Devices by that address. The steps are on A Linux box in My Devices.

    You're done when your phone shows the box in reach under Your Devices, and the box's page lists your phone as Approved.

    Day to day

    • Logs: journalctl -fu nostr-vault -u nostr-vault-mesh
    • Stop or start: sudo systemctl stop nostr-vault (the mesh stops with it) and sudo systemctl start nostr-vault
    • Settings: sudo nostr-vault-setup --show; change them with sudo nostr-vault-setup --owner … --data … --port …
    • Update: run the installer again, or apt install a newer .deb. Your data, owner and port stay. Check for update and install on the box's page says the same for now.
    • Move the vault to another drive with Move vault to… on the box's page. Choosing a different folder in the installer starts an empty vault there instead (it asks first).

    Already running the Docker box?

    A machine that runs the older Docker box keeps it when you run the installer, and the installer updates it. To move to the native app, run the install command above: its NV_NATIVE=1 stops the container and installs the package on the same data, owner and port.

    What works, and what's still beta

    Works now:

    • Your vault as a relay and media server on your network, started on boot, with the web app on http://<machine>:8080/.
    • The mesh: your phones and Macs reach the box away from home once it's in My Devices. The box makes its own mesh key and only lets in your own devices.
    • The desktop window and tray, on a machine with a desktop.
    • The box's page: status, storage and Move vault to…, the mesh, your devices, and Public on the web for a box with its own web address.
    • Moving a Docker box to native on the same data.

    Not yet:

    • No in-app updates. Run the installer again to update.
    • The download is checked against a sha256 from the same release. That catches a broken download, not a forged one, because releases aren't signed yet.
    • No native package for Arch or Fedora yet; they get Docker.
    • The plain installer, without NV_RELEASE=, only installs native once a full release carries the Linux package.

    Something wrong? Open an issue on GitHub with the output of journalctl -u nostr-vault -u nostr-vault-mesh --since today.

    Checked against Nostr Vault 3.2.3 for Linux (beta 1).
